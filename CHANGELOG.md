# Changelog

All notable changes to Ripple are documented here.

## [Unreleased]

### Added

- **An accepted ripple no longer re-bills its scene.** Accepting a judged edit already applies the verdicts and new items to the graph, so the whole-scene re-extraction that Update graph offered afterwards duplicated paid work. Acceptance now stamps each edited scene's new content as extracted, under the same synthetic-run shape the draft link uses to carry a cache, and only when the pre-edit content had a completed extraction under the current prompt and selected model: the stamp extends an extracted graph, never invents one. The judgement also widens to cross-line effects: every entity the edited lines name brings its scene-local assertions to the judge, which holds them unless the proposed text explicitly contradicts what they state ("she sets the knife down" against a carries edge cited two lines up), and a removal of such an untouched fact is admitted only when the edit names the entity.

- **Graph builds cost a fraction of what they did.** Four changes, all measured against the audit ledger that showed hidden reasoning and answer verbosity carrying ~90% of a build's spend. Every model call now caps thinking at a medium level (hidden reasoning bills at the output rate and was 38% of a build). Extraction speaks a terser output format (`extract.v5`): short field names, short unit ids in place of 36-character UUIDs on every cited item, and endpoint kinds inferred from the ids; the judgement pass (`judge.v5`) speaks the same format for new items. A deterministic pre-pass records what code can read before the model is called: the speaking cast from dialogue cues and the location from the heading, written as `system`-provenance rows citing the cue and heading lines, with the prompt handing the model their fixed ids. And extraction escalates instead of failing: a malformed, truncated, or empty reply from the main model is retried on the configured fallback model in the same pass, each attempt audited, which makes a cheap main model with a stronger fallback the recommended pairing. The validator also drops any evidence span that reaches past its line's end, keeping the item and losing the misquote.

- **A linked draft's reader tints what changed against the predecessor.** The same revision tint that marks accepted ripples now also marks the words a new draft changed: each edited line in a changed scene word-diffs against the predecessor line it revises (paired deterministically through the lineage the link already wrote, with a similarity pass for the edited lines the link leaves unlinked), heading edits tint in the scene header, and a wholly new line tints whole. A scene the previous draft did not have is chipped "NEW IN THIS DRAFT" instead of being tinted word by word, and the previous draft's own reader stays unmarked. The predecessor wording is the earlier baseline, so it wins over the in-draft accepted-edit baseline when both apply.

- **Build graph is gated on billable work.** With the graph built and every scene's content matching its cached extraction, the button disables and its tooltip says why. When scenes changed since the last build (an accepted ripple, an added or restored scene, a linked draft, a switched model), it reads Update graph and counts the changed scenes in its tooltip; only those are billed, because unchanged scenes replay from the extraction cache. The gate reads the same content hashes the cache keys on, so every path that changes a scene re-enables the button with no bookkeeping of its own.
- **Chargeable actions report their cost in money.** Graph builds and updates show tokens and dollars live in the progress counter and the finished label; the ripple preview's footer reports what the run spent (answer, hidden reasoning, and input tokens, plus the cost); the Traces page prices every audit row and totals the whole ledger in its subtitle. Prices come from the bundled `rates` registry (pypi.org/project/rates), looked up by provider and model with hidden reasoning billed at the output rate; a model the registry does not price shows its tokens alone rather than an invented figure, and a cached run reports zero. The registry ships bundled with the package and cannot fail to load; the one absence Ripple handles is `rates` itself not being installed, in which case tokens show alone.
- **Traces carry full payloads.** Tracing flips from redact-by-default to record-by-default: every model call's complete prompt, reply, and token usage (answer, hidden reasoning, input) is recorded on its trace, along with each preview's edits, each query's question and answer, each import's filename and title, and each confirmed rename's payload. KeyCall's own spans keep their internal redaction, so Ripple records its own model events beside them. The truncated audit row now also stores the reasoning-token count (`model_calls.reasoning_tokens`, shown on the Traces page), so a cut-off reply's budget is accounted for in the records instead of guessed at. Traces stay in `data/traces/`, local and out of version control; credential-shaped values are still caught by value-pattern redaction.
- **Truncation blames the reasoning budget, not the model's limit.** Models that reason before answering bill the hidden reasoning to the same output budget as the answer, so a reply can stop at the cap with the visible text well short of it. Reasoning tokens now flow through from the provider and the truncation message states them as the cause ("1476 answer tokens plus 6716 hidden reasoning tokens against the 8192 requested"); without a reported count, the budget is named as the likely cause instead of mis-reading the shortfall as the model's own smaller limit. The judgement output cap also rises from 4,096 to 8,192 tokens, matching extraction, so a reasoning model has room to think and still finish; only produced tokens are billed, so the headroom is free on models that answer within it.
- **A failed preview says what stopped and offers the trace.** The truncation error now names the model, the output tokens it produced against the tokens Ripple requested, and the finish reason, and says when the model's own output limit is the smaller one; the continuity pass's advisory note carries the same detail. The failure response also carries the TraceAct trace id of the run, and the warning banner gains an **Open trace** button: one click starts (or reuses) the local viewer and opens that trace's map, pre-filtered to the run that failed. The route passes the trace folder as an absolute path, because a viewer another project started resolves a relative path against its own working directory.
- **Renamed characters keep their identity across drafts.** The draft report inspects every cast member the new draft added and traces their speaking positions back through line lineage: a dialogue line whose text carried over but whose cue moved from one name to another is a transferred position, counted against every position of the old speaker's that carried over at all. At three or more transferred positions covering at least 80%, the rename applies on its own: the carried entity keeps its row and lineage, takes the new name, absorbs the added entity's facts, and records the old name as an alias, so a mention of either name resolves to the same character and the report says "Renamed: X to Y" instead of one removal plus one addition. Between 50% and 80% the evidence is filed as a `possible_rename` finding with the counts, and the findings page offers Confirm rename (which applies it) or Dismiss (which keeps them separate). Either way, any line still speaking under the old name afterwards becomes an open `partial_rename` finding citing the lines and scenes, the classic missed instance, reported rather than smoothed over. Cue names and canonical names differ ("NIA" against "Nia Okonjo"), so matching runs through aliases and given-name tokens on both sides.
- **The cross-draft ripple report.** Once a linked draft's changed scenes are extracted, Ripple compares the drafts through entity lineage and writes a report to the Reports page: entities added and removed with the scenes responsible, attribute values that moved with before and after, introductions that vanished while their dependants survive ("the previous draft established it in scene 3, this draft still uses it in scenes 20 and 27, and no scene here introduces it"), and continuity conflicts judged one model call per changed scene over the same evidence retrieval the ripple preview uses. The judged layer is advisory (a failed call becomes a note, never a failed report), its calls are audited on the report's change set, findings carry Review and Dismiss, and the report refuses while changed scenes are unextracted rather than mistaking missing extraction for missing content.
- **Uncertain scene matches ask instead of guessing.** A pair the aligner suspects but cannot link on similarity alone (between the weak and strong thresholds) comes up for review before the link runs, with both headings, first lines, and the similarity; ticked pairs link as rewrites, unticked pairs stay new, and cancelling cancels the link. Confirmed pairs are honoured ahead of every automatic pass.
- **A new draft continues the old one's graph.** Uploading a script whose title matches an existing script with a graph offers "Link as new draft". Linking aligns the drafts deterministically (identical content first, locked scene numbers second, order-preserving text similarity last, and nothing links below a strong threshold), then carries every unchanged scene's facts across: entities with their aliases, assertions and attributes with their evidence, resolved speakers, and the extraction-cache rows, all at zero model cost. Changed and new scenes are extracted, and only those; a scene the aligner cannot place with confidence re-extracts rather than inheriting a graph it may not deserve. An OMITTED placeholder in the new draft declares its number's scene deleted. The predecessor draft is never touched, the reader shows the chain ("Draft 2 · open draft 1"), and every scene, line, and entity records which predecessor row it continues, which is the identity renames and cross-draft reports build on.
- **KeyCall 1.8.0.**

- **Scenes can be added and omitted in the reader.** ＋ scene between any two scenes opens a dialog whose text is parsed with the same rules an imported file gets (cues, parentheticals, transitions); on a numbered script the new scene takes a lettered number per the production convention (after 12 comes 12A, above the first comes A1) and no other scene renumbers. With a model selected the new scene is extracted immediately, and only the new scene. ⊘ marks a scene OMITTED: it keeps its row and number, its facts deactivate as one accepted `omit_scene` change set (atomic, audited, listed on the Reports page), every entity it introduced that later scenes still use becomes an open orphaned-reference finding citing the surviving lines, and Restore reverses the whole thing, resolving those findings. Both operations bump the script version so stale previews refuse rather than apply.
- **Startup heals a database whose tables reference a missing table.** SQLite rewrites child foreign keys when their target is renamed, so a rename-based rebuild could leave findings, reports, and audit rows pointing at a dropped `_old` table, failing every later insert. Table rebuilds now copy data out and recreate in place, never rename, and a repair pass detects and rebuilds any child left dangling by the old pattern, keeping every row.

- **Complete ground truths for the demo corpus.** The three dependencies.md files now inventory their screenplays in full, scene by scene: NIGHT FREIGHT holds 82 entities, 40 attributes, and 480 seeded assertions across all 44 scenes; THE UNDERSTUDY 66, 30, and 354 across 41; SEVEN MINUTES 51, 27, and 315 across 29. Every stated count, colour, condition, marking, and printed text is an attribute citing its line, so an edit to any stated detail moves the graph. A coverage harness cross-checks every entity mention against the seeded edges; the remaining unlinked mentions are each deliberate (spoken references, stated absences, alias collisions) and documented.
- **Extraction demands completeness (`extract.v4`).** The prompt now declares every named object a deliverable across all ten entity types, requires the attributes array on every entity, and spells out that a stated descriptor with no attribute is a wrong answer, with the anti-fabrication rules unchanged. The output cap doubles to 8,192 tokens for denser scenes.

- **A judged continuity pass.** The evidence packet the preview already retrieves (earlier and later facts about the affected entities, each with the line that states it) is now judged by the model, one call per preview, reporting the conflicts the edit creates. A reported conflict survives only when it cites evidence ids from the packet and carries a valid severity; everything else is dropped with a counted reason in the audit row. Conflicts persist as findings with their citations in `finding_evidence`, render in the overlay and on the findings page with working Review and Dismiss, replay at no cost on a retried preview, use the fallback model, and respect the budget. The pass is advisory: a failed call degrades the preview to the deterministic findings, with a banner saying so, instead of failing it.

- **Every list page searches and paginates.** Entities, Assertions, Ripple reports, Continuity findings, and Traces share one toolbar search that filters rows as you type, and rows beyond fifty page with Previous and Next and a position readout. Both are display toggles over the rendered rows: no request, no reload.
- **A keyboard and screen-reader pass across the app.** Native hover tooltips are replaced with instant CSS tooltips paired with accessible names; graph nodes, scene rows, and library titles are reachable and activatable by keyboard; the graph search is a full combobox, with the active option tracked and announced; the Settings tab rail follows the tabs pattern with arrow-key movement and a roving tab stop; the sidebar marks the current page; toasts, progress panels, validation results, the Ask answer, and the preview summary announce their updates through live regions; the confirm dialog carries a name; touch targets grow to 44px on coarse pointers; and both graph views and the reader print their keyboard maps in the UI.

- **Findings are actionable everywhere.** The findings page rows carry Review, which opens the script, and Dismiss for open findings; the preview overlay's finding buttons now work too: Review units closes the overlay, scrolls to the cited lines, and marks them, and Dismiss records the dismissal in place. Preview responses carry each finding's persisted id to make that possible.
- **An Undo control in the reader.** After an accepted ripple, Undo last accept offers the server's one level of undo, confirmed before it runs; a refusal (a later change, a vanished unit) disables the control and says why.
- **`MANIFEST.md`**, a per-file map of the repository with an update timestamp.
- **A docs-hygiene test.** `tests/test_docs.py` fails the build when a public document or shipped source references internal planning material, when a README link is relative, or when the manifest misses a shipped file.
- **`USAGE.md` is a full manual.** It walks the application in order of use: launch, the library, settings, graph building, the graph views, editing and the ripple preview with its refusal and failure code tables, findings, Ask the graph, the list pages, tracing, and the import reference. The rejection-code table now includes the live `empty_document` code.

- **The preview is judged against the stored graph.** The old preview blind-extracted the proposed text and diffed two extractions, so a changed dress color read as "nothing changes" whenever the two extractions happened to agree. The new engine (`ripple/services/preview.py`, `ripple/extraction/judge.py`) sends the model the stored assertions and attributes the edited lines support, each with its id and evidence, and asks for a verdict per item: `holds`, `changed`, or `removed`, plus any new items with cited evidence. Verdicts are verified in code before anything persists: an unlisted id is dropped, a duplicate is dropped, `holds` on evidence the edit deleted is downgraded to `removed`, `changed` without a value collapses to `holds`, a missing verdict for a listed item is a coverage miss that fails the preview, and new items pass the same validation as extraction.
- **One proposal can span many lines.** Every draft on the page rides along in one request (`POST /api/scripts/{id}/preview`), judged one scene per model call, recorded as one change set, and accepted or rejected as one decision. The single-unit endpoint delegates to the same engine.
- **The changed words are highlighted.** Each edited line renders as a word-level diff, deletions struck through and insertions marked, computed in code with no model involvement.
- **Attribute changes are their own card.** A judged `color: emerald → red` shows entity, key, both values, and confidence, floors the ripple's severity at medium, and applies as a `set_entity_attribute` operation that acceptance writes and undo reverses.
- **An identical preview is not billed twice.** A repeat of a pending proposal with the same units, texts, and base versions is rebuilt from the stored operations, findings, and report, with no model call, and says so in the overlay.
- **A failed judgement persists nothing.** A provider error, a truncated reply, or a malformed reply raises instead of storing a half-judged proposal; retryable codes are retried once. Every call is still written to the `model_calls` audit table with its outcome, and the refusal states (nothing changed, no graph, no model, edits spanning two scripts) each return a code and a next step before any provider contact.
- **Extraction reads attributes (`extract.v2`).** The extraction contract's entities now carry an `attributes` array: "the emerald gown" comes back as a gown with `color: emerald`, each attribute citing the unit and character span that states it. The validator enforces the same fabrication rule as assertions (an attribute citing an unshown unit is dropped), normalizes keys so "Color" and "color " cannot become two rows, keeps the first value on a duplicate key, and holds the confidence floor. Extraction never overwrites an active value: a value stated in scene 3 is not replaced by scene 40 restating it, and changing a stored value stays the judgement engine's job through an accepted change set. The prompt version bump invalidates the extraction cache by design. Evidence offsets are bounded in the output schema (0 to 100,000): live testing caught a model free-running hundreds of digits into an unbounded integer field until the reply blew the output cap, and a bounded field removes that failure at the decoding layer.
- **Dead models are marked in the picker.** A live call failing with `model_not_available` records the model as unavailable on this account, and the Settings picker disables it with "unavailable on this key". A later successful call clears the mark. The mark comes only from recorded call outcomes: the provider's catalog cannot state account-level entitlement.
- **The model explanation is opt-in.** `POST /api/changes/{id}/explain` writes prose for an existing preview on request; the always-shown summary is assembled deterministically from the diff, so explanation prose never adds a call to a preview.
- **A Traces page, fed by every call site.** Extraction, judgement, synthesis, and grounded query all write a `model_calls` row: prompt, reply, token counts, duration, outcome, and a validation summary. The Traces page lists them newest first with the spend ledger in the header, and the sidebar carries the running count. Rows are application data, deleted with their script, distinct from TraceAct's redacted operational traces; the `ripple.preview` and `graph.query` workflows are now TraceAct-traced alongside import, extract, accept, and undo.
- **A token budget with a hard gate.** Settings shows the recorded spend (calls, tokens in, tokens out) and takes one number: a cap on total recorded tokens. When the total reaches it, every call site refuses before contacting the provider, writes the refusal to the audit table as `budget_refused`, and names the fix. The preview refuses with a code, extraction fails the scene without retrying, and synthesis and query fall back to their deterministic output. Refusals carry no token counts, so they cannot compound the spend. Clearing or raising the budget reopens the gate.
- **A fallback model.** Settings takes a main model and an optional fallback. When the main model refuses for an availability reason (dead on this key, a provider outage, a rate limit, a timeout), the same call runs once against the fallback, at every call site: judgement, extraction, synthesis, and grounded query. Both attempts are written to the Traces audit, written rows record the model that answered, and a malformed or truncated reply never fails over, since that is not an availability problem. A fallback equal to the main model is refused with the reason.
- **Settings is tabbed.** A tab rail with one category per tab (API keys, Spend, Interface) replaces the single scrolling page, and the chosen tab survives a reload. The API keys tab carries the credential card and the main and fallback model pickers, both saved the moment they change.
- **Page errors render in the app.** A stale bookmark or a deleted record on a page route now shows an in-app view naming what happened and offering the library and a back link, instead of a bare JSON body. API routes keep their JSON errors.
- **Clicking a selected graph node deselects it**, clearing the edges, the highlight, and the detail pane. Escape does the same.
- **Edges are drawn by family.** The nine predicates group into five line treatments: presence (`appears_in`, `occurs_at`) is a quiet solid line, handling (`wears`, `carries`, `uses`, `travels_by`) is dotted, dependency (`requires`) is dashed in amber, `establishes` is a dashed accent line over a soft glow, and the symmetric `interacts_with` is a wide soft band. Directed families animate their dashes toward the assertion's object and carry a mid-edge arrowhead, so direction survives with animation off under reduced-motion settings. Type is never carried by colour alone: the dash pattern and the printed predicate say the same thing, and the canvas legend shows each family's line.
- **The graph zooms and pans.** Zoom controls render bottom-right of the canvas (buttons, live percentage, reset), plus mouse wheel to zoom under the cursor, drag to pan, and arrow keys/+/-/0 to pan and zoom when the canvas has focus. Both the script-level and expanded graph views carry it.
- **A search bar finds a scene or entity and selects it.** Typing in the graph toolbar's search filters live over every node's label; picking a result (click, arrow keys, or Enter) runs the same selection path a click does, dimming everything unrelated and filling the detail pane, then centres and zooms the graph on it.
- **The findings chip opens the findings.** The reader's continuity-findings count is now a link to the findings page filtered to that script (`/findings?script={id}`), so the notice leads to the items it counted. The count also reads "1 continuity finding" instead of "1 continuity findings".
- **The version shows beside the mark.** Every page's top-left corner carries the installed package version, so a screenshot says which build it came from during troubleshooting. It reads "dev" when no package metadata is present.
- **Edge labels no longer pile up at hubs.** A node with many edges put every label at its own curve's midpoint, and those midpoints converge near the node, printing labels on top of each other. Each edge now takes its label position from its place in the busier endpoint's fan, cycling through depths along its own curve, and a second pass nudges any label that still overlaps a node or an earlier label until it is clear, with the escape direction held so a label caught between two obstacles cannot bounce in place. Deterministic and bounded: the same graph draws the same way every time. Verified overlap-free on every node of all three demo scripts.
- **An unnumbered scene shows an honest placeholder.** An intercut sub-heading or an OMITTED slug has no scene number, and the graph used to substitute the scene's position, inventing a number that collided with a numbered scene further along the spine. Those scenes now show `Sc —` on the graph and in entity scene lists.
- **Selection dims the unrelated graph.** With a node selected, everything neither selected nor connected to it drops back, so the selection and its edges carry the view. Opacity works alongside the accent ring and the drawn edges, so the emphasis survives colourblindness, and the fade respects reduced-motion settings.
- **Scripts open on the script.** Clicking a script in the library opens the reader; a Settings choice, saved the moment it changes, switches the opening view to the production graph instead. Either way the other view stays one click away.
- **The demo corpus opens with its graph.** Every bundled screenplay's `dependencies.md` now carries its full expected entities, aliases, and attributes, and the application seeds each script's ground-truth graph from those tables at startup: 60+ entities, 40+ aliases, 10 attributes, and 260+ assertions across the three scripts, written with `provenance="system"` and zero model calls. Seeding is idempotent and a cleared graph reseeds on the next start. `tools/seed_graph.py` runs the same builder by hand.
- **The script-level graph is the opening view.** Opening a script from the library goes to its full production graph: every scene on a two-row spine in script order, every entity in its department wedge, filters for department and confidence. Edges draw for the selected node, so the view stays readable at any script size. The reader is one click away and links back.
- **Entity detail card.** Clicking an entity shows its type, description, aliases, typed attributes with their evidence lines, every assertion it participates in, and the scenes it spans.
- **Entity attributes.** An entity carries evidence-backed key-value facts (`color: emerald`, cited to the line that says so), one active row per key, with model-provenance rows required to cite evidence. An attribute change is now a production event of its own instead of a naming coincidence.
- **A model-call audit record.** Every model interaction can be recorded in full (prompt, raw response, token counts, outcome, validation report) as application data, deleted with its script, distinct from TraceAct's redacted operational traces.

- **`ARCHITECTURE.md`.** Project structure, a system diagram from upload through extraction, diff, continuity, synthesis, and change-set acceptance, the data stores and external integrations, and a glossary of the domain terms (unit, scene, entity, assertion, predicate, ripple, change set, continuity finding, extraction run).
- **`Cache-Control: no-store` on every response.** A tab kept last version's HTML, CSS, or JS after a local restart with no visible sign anything was stale. The existing mtime-based `asset_version()` query string still busts the cache on a file change; this also covers the HTML entry point and a server restart with unchanged files.
- **A failed provider call is now visible in the ripple preview**, instead of looking identical to an edit with no graph impact. `_extract_proposed` and `synthesize` used to catch every `ProviderError` (a dead model, a rate limit, a truncated response) the same way they handle no provider being configured at all: silently, falling back to an empty diff or a deterministic sentence. The preview response now carries `extraction_error` and `synthesis_error`, and the preview overlay shows them as a banner rather than presenting a confident-looking empty result. Caught testing against a live key: `gemini-2.5-flash`, the selected model, had gone dead on the account. Gemini's model-listing endpoint carries no lifecycle field, so the catalog can't say this on its own: it's an account-specific entitlement problem, not a global deprecation KeyCall's schema could encode. KeyCall's own `model_not_available` error code is the live-call signal for it, and now gets a specific next step appended: "Pick a different model in Settings."
- **Settings no longer tags the provider "ships with the submission."** With Gemini the only provider, the tag was always true and said nothing.
- **A frontend decision log.** Every handler records what it decided as it decides it: API call outcomes with status and timing, preview results and failures, accept/reject outcomes, extraction run progress, draft transitions, and settings changes, in a bounded in-page ring buffer that is always on. `ripple.debug()` dumps it, `ripple.debug('preview')` filters it, `ripple.debug.table()` renders it as a table. Records mirror to `console.debug`, so browser-side tracing tools that capture console output persist them. Credentials never reach a record.
- **Confirmations render in-app.** Discarding drafts and deleting a script asked through `window.confirm`, a bare browser dialog that can't be themed and blocks the page. Both now use a shared in-app dialog with keyboard focus trapped inside it and Escape to cancel.
- **`api()` distinguishes an unreachable server from a rejecting one.** A network failure now reads "The server is not reachable. Is Ripple still running?" instead of the browser's raw fetch error.
- **A continuity warning no longer cites itself.** `detect_orphaned_references` checked whether an entity's "use" edges survived a proposal by querying `active` assertions, with no exclusion for a use the same diff also removes: a proposal isn't applied until accepted, so that edge is still `active` in the table. An edit dropping both an entity's only establishing line and its only use in one unit was flagging "Later units still reference X", citing the unit being edited as the surviving later reference. Caught live on NIGHT FREIGHT scene 14, removing "Dead forklift". `detect_orphaned_references` now takes every assertion id the diff removes, across every predicate, and excludes all of them from the survival check, not just the removed `establishes` edges.
- **Provider adapters now run on KeyCall 0.10.0**, and Gemini is the only provider left. `ripple/llm/keycall_provider.py` replaces the three hand-rolled wrappers (`gemini.py` over `google-genai`, `anthropic_provider.py`, `openai_compatible.py` over `openai`) with one class, parametrized per provider. Credential validation, model listing and filtering, and structured-output enforcement are now KeyCall's job rather than Ripple's: `strip_code_fence` and `explain_auth_failure` are gone from `ripple/llm/base.py` because KeyCall already returns valid JSON text for a schema-constrained call and already returns a typed, actionable error for a rejected key. `pyproject.toml` drops `google-genai` and the `openai`/`anthropic` extras. OpenAI, Anthropic, and DeepSeek are gone from `PROVIDERS` entirely rather than staying as dev-only entries to strip before submission: development and testing now go through Gemini, the only provider Ripple runs against.
- **The script is editable in place.** Every line is a `contenteditable` block. Typing marks it "edited, not applied" in amber, the toolbar counts unapplied edits, Escape reverts a line, and Revert edits discards them all. Drafts live only in the page: the accepted script is unchanged until a ripple is accepted, which is the guarantee the product rests on. Enter opens the ripple rather than splitting the unit, and paste is flattened to plain text, because both would otherwise produce markup the parser never emitted.
- **Credential checks no longer guess at key formats.** The Gemini adapter briefly refused any key not beginning `AIza`, which would have rejected the `AQ.` keys AI Studio now issues. A local check may only refuse what cannot be a credential in any format: JSON file contents, or a value containing whitespace. The provider decides everything else.

- **Collapsible side panes**, with the choice persisted per pane. The sidebar collapses on every page; the reader's requirement pane and the graph's detail pane have their own toggles. Below 900px the sidebar becomes a drawer over the content with a backdrop, because a 238px column at that width leaves nothing for the script.
- **Asset cache-busting.** Every stylesheet and script carries a version derived from the newest file modification time. Without it a browser keeps a stylesheet it already has and runs old CSS against new markup, which fails invisibly: the file on disk is right, the served file is right, and only the loaded sheet is stale.
- **Responsive breakpoints**, verified by measuring the rendered page at 1600, 1024, and 480 pixels rather than by inspection: no horizontal scrolling at any of them, the reader stacks below 1080px, the graph panes stack below 820px, and the library drops its lowest-value columns below 640px.

- **Graph rendering, 2D.** A deterministic server-side layout in `ripple/graph/layout.py` places the focus at the centre, scenes on a horizontal spine in script order, and entities in fixed angular wedges by department, so a department occupies the same region in every view. Drawn as hand-rolled SVG: no graph library, no WebGL. Parallel edges fan apart and stagger their labels along the edge by an amount computed from the label width and the edge length.
- **Expanded graph view** at `/graph/{unit}` with department filters, depth 1 to 3, a minimum-confidence threshold, a removed-edge overlay, and a detail pane listing a selected node's edges.
- **`tools/seed_graph.py`**, a developer command that writes the graph a correct extraction should produce for scene 14 of the first demo script, taken from that script's `dependencies.md`. Rows carry `provenance="system"` so they are distinguishable from a model's output. Nothing calls it automatically.

- **Analysis and Graph pages**: Ripple reports, Continuity findings, Entities, and Assertions. These were linked in the sidebar before they existed, so every one of them 404'd.
- **Recently opened** is a working filter. `Script.last_opened_at` is set when the reader displays a script, distinct from `updated_at`, which moves on any write: a script changed by an accepted edit was not thereby opened.
- **Locked features look locked.** A control that cannot work is disabled, greyed, and accompanied by a banner naming the missing prerequisite with a link to it. Applied to Ask the graph and the Entities and Assertions pages when no graph exists, to Build graph when no model is selected, and to Validate and Save in Settings until a key is typed.
- **Independent pane scrolling.** The reader's scene list, script, and requirement pane each own their scroll, as do the two columns of the ripple preview. Scrolling the script no longer drags the requirement pane off screen.

- **The UI rebuilt against the design mockups.** App-window shell with a fixed sidebar carrying live counts, a toolbar per screen, a script table with format, pages, scenes, runtime, and import outcome, a reader whose sidebar lists scenes with page, eighths, and entity counts, and a full-screen ripple preview with the accepted and proposed text side by side, the graph diff, continuity findings, per-stage pipeline timings, and source provenance.
- **Change-set service.** Atomic acceptance with base-version checks, rejection that changes nothing, and latest-only undo through an inverse change set. The original becomes `reverted`, never `rejected`. A unit's wording moves through a `set_unit_text` operation carrying before and after, which is what makes undo able to restore the original text.
- **Synthesizer.** Explains a diff the engine already computed, and is given only that diff and the findings, never the screenplay. Severity is computed in code so it cannot vary between runs. With no provider configured it assembles a deterministic sentence from the diff instead of failing.
- **Grounded query.** Answers from accepted assertions only, records the assertion ids it was allowed to use in `query_log`, and falls back to listing the matching assertions when no model is configured.
- **Pages, runtime, and eighths**, calibrated against the demo corpus, where each Fountain source has a rendered PDF with a known page count.

- **Web application.** Script library with import and deletion, a reader that renders screenplay units at their proper indents, a requirement pane, provider settings, and the browser-driven extraction loop. `./launch.command` installs, picks a free port, starts the server, and opens a browser; `--test` runs the suite instead. The library seeds the demo corpus on first run.
- **Deterministic diff engine.** Compares accepted and proposed assertions by edge identity, since a proposed edge has no row yet. Entity endpoints are keyed on `(type, normalized name)`, matching the database's uniqueness rule. Symmetric predicates are ordered canonically so a reversed `interacts_with` is not a change. A removal and an addition sharing a subject and predicate group into one change, but only when the slot holds one of each: two out and two in is a rewrite, and pairing them would be invention.
- **Continuity retrieval.** Deterministic gathering of earlier and later assertions on affected entities, aliases, direct neighbours, and the units supporting them, ranked and bounded before it reaches a prompt.
- **Orphaned-reference detection**, determined in code with no model. When an edit removes the only `establishes` edge for an entity later scenes still use, the warning holds whether or not the continuity agent is available.

- **Scene-level graph extraction**, resumable and browser-driven. One scene is claimed per request through an atomic `UPDATE ... WHERE status='pending'`, so two tabs polling at once cannot extract and pay for the same scene twice. Each scene commits independently, so a failure late in a run keeps everything before it.
- **Extraction cache.** A scene already extracted from identical input under the same prompt version and model gets no job created at all: no row, no call, no spend. Editing any unit changes the content hash and invalidates it.
- **Output validation against the predicate signatures.** They live in `ripple/graph/predicates.py` and are rendered into the prompt from the same source of truth. An assertion citing a unit the model was never shown, violating a signature, or falling below the confidence floor is dropped with a recorded reason rather than repaired. One bad assertion never loses the good ones in the same scene.
- **Provider settings.** Per-provider credential entry, validation against the provider's own models endpoint, and model selection. Keys go to the process environment and a gitignored `data/secrets.env` at mode 0600, or to Replit Secrets in production; never to the database and never back to the browser, not even masked. An invalid key is not stored.
- **Fixture provider** for deterministic tests without a credential. Absent from the shipped registry, and an unrecorded prompt raises rather than answering emptily, since an empty extraction is a legitimate outcome.

- **SQLAlchemy models for all 18 tables**, with kinded assertion endpoints so a scene can be a graph node. Enumerated values are CHECK constraints rather than native enums, keeping the schema portable between PostgreSQL and SQLite.
- **Persistence layer.** `persist_import` writes a parsed screenplay and its provenance; `delete_script`, `delete_all_scripts`, and `clear_all_graphs` return their counts before anything is removed.
- **Foreign keys enforced on SQLite** through a per-connection pragma, so local tests prove referential integrity rather than appearing to.
- **LLM provider adapters** for Google Gemini, OpenAI, Anthropic, and DeepSeek behind one contract. Model lists are read from each provider's own endpoint, never hardcoded, and filtered to text generation. Only Gemini ships; the other three were development aids, since removed.
- **Title extraction** from the Fountain title page and the Final Draft `TitlePage` element.
- **`script_units.speaker_name`**, so a reload between import and extraction does not lose who was speaking.
- **Third demo screenplay**, SEVEN MINUTES, targeting graph behaviour: accented names, an omitted scene, an intercut, an entity that changes state, and an identity that resolves only in the final act.

### Fixed

- **A one-word edit can no longer read as "nothing changes".** Editing "Six monitors" to "Twelve monitors" produced "No graph change" because the graph never held the monitors; with the complete ground truths the same edit now answers with the count attribute change at medium severity. The preview's summary also states what it judged ("All N stored facts the edited lines support still hold") and, when an edited line supports nothing stored, says the graph is incomplete rather than implying the edit has no impact.
- **Ground-truth seeding could touch a user's upload.** Startup seeding selected scripts by title, so uploading a script named NIGHT FREIGHT and restarting would mix the bundled ground truth into its extracted graph, with evidence spans pointing at another document's lines. Scripts now carry an `origin` column: the startup importer marks its own imports `bundled`, and seeding refuses everything else. Existing databases get the column on start, with pre-existing demo scripts re-marked only on evidence (a system-provenance graph and no extraction history), never on a title match alone.
- **The confidence numbers explain themselves.** The decimals on requirement rows, attribute-change cards, and graph detail panes now carry hover text ("Confidence: the model's certainty this fact is stated, from 0 to 1"), reachable by keyboard and named for screen readers.
- **OCR of a multi-page scan wrote page images into the working directory.** pdftoppm treats any trailing argument, including `-`, as a filename prefix, so a two-page scan dropped `--1.png` and `--2.png` beside the app and fed OCR broken input. The rasteriser now runs one page per pass with the output root omitted, the only mode that writes to stdout, so nothing touches disk and every page reaches Tesseract; a regression test asserts an OCR import leaves the working directory empty.
- **A removal must be visible in the edit (`judge.v3`).** The judge could answer `removed` for edges whose entities the proposed text still names, and for facts the edited line never stated, because uncited facts fall back to citing a scene's first unit; a count change then produced five phantom removals and a false orphan warning. Two validator guards now downgrade those to holds: a removed verdict stands only when some endpoint was named in the current text and is gone from the proposed text, and an attribute can only change through a line that visibly carries its value. Both downgrades are recorded in the audit row.

- **The launcher finds a working Python instead of trusting PATH's `python3`.** A version manager's pin can hold `python3` below 3.11 while newer interpreters are present and working; the launcher now reuses a valid venv without needing a system Python at all, and otherwise probes version-named binaries and the usual install locations, judging each candidate by running it.
- **Predicates print as words in the UI.** Edge labels, requirement rows, detail panes, and the Assertions page show "appears in" rather than `appears_in`; the stored vocabulary is unchanged.
- **The launcher stops a stale server instead of adopting it.** `launch.command` now terminates any running Ripple instance before touching the environment, so two servers can never share the SQLite file. It also verifies Python 3.11 or newer with an actionable message, rebuilds a broken virtual environment instead of failing on it, and takes over a port held by another Ripple instance rather than skipping past it.
- **The virtual environments and runtime data are excluded from Dropbox sync.** The launcher marks `tools/.venv`, `.venv`, and `data/` with the ignore marker on every start, so sync can no longer invalidate the environment mid-run or replicate `data/secrets.env` off the machine.
- **Server rejections reach the page as sentences.** A 422's field-error array rendered as "[object Object]" and other failures as "Request failed (500)"; `api()` now assembles a readable sentence from whatever the server sent, error-code badges print their words instead of snake_case, and the error page labels its number as an HTTP status.
- **Import warnings survive the library's reload.** The import outcome and its warnings are stashed across the reload that shows the new row, instead of being wiped after 0.9 seconds.
- **Forgetting a key asks first.** The Settings Forget button confirms before deleting the stored credential.
- **`tools/seed_graph.py` explains an empty database.** Run before the corpus was ever imported, it printed success and seeded nothing; it now exits with an error naming the fix: launch the app once so the library imports the corpus.

- **A selection made before the graph's own layout settled could render without dimming the rest of the graph.** `draw()` defers itself with `requestAnimationFrame` when the canvas reports a momentary zero size (right after navigation, a pane toggle); the dim pass was a separate statement after that call, so a selection made during that window ran the dim check against zero nodes and the drawn ones showed up afterward with no dim state at all. The dim pass is now `draw()`'s own completion callback, so it runs against the nodes on the page, whether that's the immediate draw or the deferred one.
- **Accepting a "changed" assertion applied nothing.** The update handler deactivated the old edge and then routed through the addition's reactivation fast path, which re-activated the row it had just deactivated and never read the new edge. Every accepted update now writes the new edge from its payload, and undoing one restores the old edge.
- **Failed and refused model calls now reach the ledger.** A judge call that failed, and a budget refusal, wrote their audit rows and then lost them when the request's transaction rolled back, so billed work was invisible to the spend cap. A failing preview now commits its audit rows and the model-availability marks before the error propagates; nothing else is pending at any point the preview can fail.
- **A judged scene is never re-billed.** A preview retried after a failure elsewhere replays each already-judged scene from its recorded reply, written to the audit as a `cached` call with zero tokens. Judge calls are also linked to the proposal they produced through the calls the preview itself made, instead of a newest-unlinked query that could attach another request's calls.
- **An empty judge reply no longer passes as "No graph change".** A schema-valid reply that skipped listed items used to default every one of them to `holds`; any coverage miss now fails the preview with `incomplete_judgement` and an `incomplete` audit row.
- **A hold cannot survive on deleted text.** The vanished-evidence guard accepted any in-bounds offset pair without comparing content; the offsets escape is gone, and only the evidence text still appearing in the proposed line keeps a `holds` verdict alive.
- **Stale proposals are recorded as stale.** The status write raised with the 409 and rolled back with it, leaving the proposal pending and matching the preview cache forever. The web layer now re-applies the status in a fresh session, and the same path records a proposal whose unit vanished as `failed`.
- **Entities created through accepted changes keep their cased names.** Operation payloads carried the normalized key, so a judged new prop "The Brass Key" was stored and displayed as "brass key". Payloads now carry the display name; lookups normalize either way.
- **Screenplay-derived text is escaped before it reaches the page.** Names, unit text, evidence, warnings, and model output flowed into `innerHTML` unescaped in the reader, both graph views, Ask, Settings, and the library, so an uploaded script could run markup in every page that rendered it. A shared escape helper now covers all of them.
- **Extraction run status tells the truth.** A run that finished with failed scenes reported `ready`; it now reports `partially_ready`, and `ready` is reserved for a run every scene of which completed. A run whose every scene is served from the cache finishes immediately instead of staying pending with nothing to claim.
- **Settings validation never touches the process environment.** A key under validation was written into `os.environ` for the duration of the network call, so a concurrent extraction could read the wrong key; the candidate now rides the call itself and is discarded.
- **The preview's continuity context is scoped and ordered.** Open findings from other scripts no longer enter the evidence packet, and the earlier/later split anchors on the earliest edited scene in script order rather than whichever edit came first in the request.
- **Invented scene numbers are gone everywhere.** The "Sc —" fix reached only one of three label maps; preview citations and continuity payloads could still name a position as a number that belonged to a different scene. One shared label map now serves the web layer, the preview, and continuity.
- **New-assertion endpoints resolve by type.** A judged edge citing an existing entity by name matched on the name alone, so a prop and a transportation entity sharing a name could take each other's edges; matching is now constrained to the types the predicate accepts on that side.
- **Evidence offsets are a pair or nothing.** A half pair like `(null, 42)` survived validation and silently slid to the start of the unit; both offsets now arrive together and ordered, or neither does. The judge also refuses an out-of-range confidence instead of clamping it, so a claimed confidence of 87 no longer becomes a trusted 1.0.
- **The extraction cache key covers the prompt.** Editing the rules or the schema changed every prompt without changing `PROMPT_VERSION`, so cached extractions were served against a prompt they never saw; the content hash now folds in a fingerprint of the prompt material.
- **Opening a script is a POST, not a side effect of the GET.** The reader's GET wrote `last_opened_at`, so a prefetch or a crawler reordered Recently opened; the reader and script-graph pages now report the open themselves.
- **Stale links answer honestly.** `/ask` with an unknown script fell back to the newest script and `/findings` widened to every script, both silently; both now answer 404. The graph-lock notice is scoped to the page's own script, and one script's deletion preview no longer counts every script's findings.
- **Unexpected server errors answer in the app's own voice.** A `ValueError` from the extraction service surfaced as a bare 500, and any non-HTTP exception on a page route bypassed the error view entirely; both now render the in-app error page (or JSON on API routes) with the details kept to the server log.
- **The graph page stopped burning a core.** A selection made with the requirement pane collapsed requeued `draw()` through `requestAnimationFrame` forever against a zero-size canvas; the retries are bounded. The expanded view's selection also applies its highlight to the clicked node (it compared labels, so same-named nodes cleared each other), survives a window resize with its dim state, and the reader's mini graph no longer traps page scrolling under the wheel.
- **The preview overlay's buttons follow the server's state.** Rejecting a proposal cleared it from the page so a later Accept could not hit a rejected proposal, drafts compare through non-breaking spaces so a retyped line stops counting as edited, See ripple disables when no draft exists, and switching lines mid-load can no longer let the first line's late replies overwrite the second's panes. Ask sends one question at a time.
- **Seeding survives edge input.** A heading-only scene and a ground-truth row with an empty name both crashed the startup seeder; both are skipped now.
- **Undo covers entity operations.** A change set holding `create_entity` or `update_entity` had no inverse mapping and crashed the undo with a bare KeyError; both invert now, and acceptance and undo traces record the change set and unit they were given even when they fail.
- **The suite runs without the live credential.** The web fixtures point the secret store at an empty file through `RIPPLE_SECRETS_PATH`, so startup cannot repopulate the key a test just removed, and the settings and provider tests run against stubs instead of the live endpoint.
- **Text selection was unreadable.** The browser default left grey secondary text on a pale blue block.
- **Ask the graph sent a null script id**, because the page read the script from a query parameter the server had not put there. It now comes from the server, which also handles the fallback to the most recent script.
- **Unnumbered scenes were given invented numbers.** Intercut sub-scenes carry no number of their own, and substituting the position produced a sidebar listing two scene 9s.
- **Accented character cues were parsed as action.** The cue pattern used `[A-Z0-9]`, so `MATÍAS` and `BÉLA` fell through to action lines and their dialogue lost its speaker. The pattern is now Unicode-aware. Found by rendering the third demo script, which was written to carry this trap.

## [0.1.0] - 2026-08-01

### Added

- **Import adapters for four formats.** Fountain, Final Draft XML, PDF, and plain text behind one contract: detect, extract, parse, validate, return a shared typed result. `import_screenplay` never raises for bad input; a file that cannot become a screenplay returns a rejected result with a stable code.
- **Content-based format detection.** File extensions are hints that can break a tie between two text formats and never override a content signal.
- **Structural screenplay check.** A parsed document is judged on scene count, character-and-dialogue presence, dialogue share, and mean action length before it is accepted, so prose and invoices are rejected with stated reasons.
- **PDF layout parsing via pdf-inspector.** Local classification and position-aware extraction, no network calls and no models. Blocks are classified against the page's own modal left margin and split on vertical spacing, page break, or horizontal offset. Scanned PDFs rasterise through `pdftoppm` and read through `tesseract`, both local; when either is absent the import is rejected with `ocr_unavailable`.
- **Hardened XML parsing.** Final Draft files go through `defusedxml`. External entities and entity expansion are refused, pinned by billion-laughs and XXE tests.
- **TraceAct 0.12.0 instrumentation** on the `script.import` workflow, with automatic input capture disabled and the `ai_prompts`, `api_keys`, `http`, `filesystem_paths`, and `env_vars` redaction presets. Tests assert that no screenplay line, character name, or filename appears in any trace.
- **Demo corpus.** Three original screenplays, each authored in Fountain and rendered to Final Draft XML, PDF, and plain text by `tools/render_screenplay.py`. Each ships a `dependencies.md` recording expected entities, assertions, and planted dependency chains.
- **`launch.command`.** Path-safe bootstrap that creates the virtual environment, installs the package, and runs the test suite.
