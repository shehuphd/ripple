# Changelog

All notable changes to Ripple are documented here.

## [Unreleased]

### Added

- **Ask Ripple: a conversational agent that works across the script.** The Ask the graph page becomes a chat over one script. A question ("which scenes include the blue sedan?") is answered on the grounded path, from accepted assertions with cited evidence, at the same cost as before; a change request ("we lost the harbour location, tell me what breaks and fix it") opens a conversation in which Ripple searches the graph, computes every scene an entity's coverage touches, reads the affected scenes, states a per-scene plan, drafts the changed lines, and runs the drafts through the same judgement and continuity passes as any hand edit. Nothing applies from the chat's model side: the tool surface has no accept, reject, or undo, and applying is a Confirm button on the page. The plan renders before any drafting spend with **Go ahead** and **Adjust the plan** beside its cost so far; the ripple card that follows drafting carries **Confirm**, **Revise** (the proposal is withdrawn and redrafted with the feedback folded in), and **Cancel**. After Confirm, the reply names the version move, tables what applied per scene, lists the continuity findings still open with a link into the reader, and states the turn's model calls, tokens, and cash cost, logged in the ledger as one grouped action.

- **Conversations persist beside questions.** Each history has its own searchable pane: conversations on the left, single questions on the right. Both replay from storage at no cost, and closing a conversation rejects any proposal it left pending so nothing waits unattended. A new conversation is named by its opening request.

- **A confidence floor gates what Ripple proposes.** A fact the judge scores below the floor (0.7 by default, configurable in Settings, off at zero) is removed from the proposal before it is offered and named on the card with its score, so a doubtful change is reported rather than slipped into an otherwise good change set. The text edit stands; only the doubtful fact is withheld.

- **The agent is fenced the way the ask path is, and further.** Screenplay text and tool results reach the model only between markers carrying a per-turn random sentinel, with lookalike markers neutralised first, so a planted line cannot close its own fence or claim new permissions. Every tool argument is validated against the conversation's script, drafts pass a minimal-edit guard (the line must exist in the scene, must change, and must keep most of its own words), the drafter runs toolless behind a response schema, tool calls stop at the per-turn ceiling from Settings, and every model call is recorded in the audit trail and counted against the budget cap like every other.

- **Settings holds the Ask Ripple controls, and its sections say what they configure.** The rail reads Models (the credential beside the model choice it configures), Spend (the budget cap beside the ledger it governs), and Interface. Interface gains an Ask Ripple section: **Draft around a cut** chooses whether omitting a scene also proposes patches to the neighbouring scenes or reports what breaks and stops; **Show the plan before drafting** decides whether the coverage list renders before any drafting spend; **Tool call ceiling per turn** caps model-directed calls inside one turn on top of the token budget; and **Keep conversations per script** decides whether conversations persist beside question history. Each control writes its preference the moment it changes, a value the app does not recognise is refused with the ones it does, and a ceiling stored out of range falls back to the default rather than uncapping a turn.

- **A graph build runs on the server, so leaving the page no longer stops it.** Extraction used to be driven by the browser, one request per scene, which tied a long build to an open tab. A worker thread now drains the run and the page polls its progress, so a build survives a reload, a navigation, or a closed tab, and the build screen says so. Cancel still asks twice and still stops after the scene in flight; a cancelled run stays cancelled even when that last scene finishes. Both build screens report what the run has put in the graph beside what it has spent ("1,614 assertions extracted · 84,120 tokens · $0.12"), with the pace per scene beside it on the Ask page. SQLite runs in write-ahead logging so the worker's writes never block a page reading progress.

- **A current graph offers a rebuild.** Once every scene matches its cached extraction, the toolbar button reads **Rebuild graph** instead of going dark: pressing it confirms first (it reads every scene again with the model and bills for each), then forces the run past the cache. The parser and the deterministic pre-pass improve between builds, and neither is reflected by replaying a stored answer, which is what a rebuild is for. Facts already in the graph stay; a rebuild adds and refreshes.

- **Graph nodes can be dragged.** A node follows the pointer with its edges redrawing live, and Shift with the arrow keys nudges the selected node, so a crowded neighbourhood can be spread by hand. A drag past a few pixels never counts as a click, positions hold across filter changes on the same page, and a reload returns to the computed layout.

- **The reader's scene list searches as you type.** A search box above the scene list filters live over headings and scene numbers, with a "nothing matches" line when the filter comes up empty; on a play whose sidebar runs to dozens of scenes, typing beats scrolling.

- **The graph detail pane names its sections in department colour.** The Attributes and Assertions headings render as chips in the selected entity's department hue, so the pane reads as part of the same coloured world as the canvas.

- **A printed play's front matter stops leaking into the scene list.** A contents listing at the top of a Gutenberg play used to import as phantom scenes (headings with no lines under them), and a dramatis personae page's roster as cast entities; both are recognised and dropped, with the survivors renumbered and the drop recorded as an import warning. A cue name wrapped in the italics underscores Gutenberg uses ("_Hamlet._") reads as the plain name.

- **Destructive and disabled controls say so the same way everywhere.** Destructive actions (Delete, Dismiss, batch deletes) share the red treatment and confirm in red; disabled controls carry a tooltip naming why they are off and what enables them, instead of going quiet.

- **"Needs review" now shows what to review, and a full act imports whole.** A needs_review script used to carry the label and nothing else: the importer's warnings were stored in the database and no page rendered them. The reader now opens with a banner naming each stored warning and a **Mark reviewed** button that moves the script out of the review queue once a human has looked (the status becomes accepted-with-warnings, and the import record keeps the original outcome); the library row states the warning count under the outcome, with the messages in its tooltip. The trigger behind the corpus's own flags is also fixed: the per-scene unit ceiling was sized for a screenplay scene, and a stage play's acts are its scenes, so a full act of Chekhov or Wilde was silently cut at 500 units and everything after it never imported. The ceiling now holds a full act, and it remains a guard against a pathological parse rather than a trim on literature. Extraction's own output ceiling rises with it: hidden reasoning bills against the same budget as the answer, and on a full act the model spends thousands of tokens thinking before it writes, so the old ceiling cut the answer off mid-scene.

- **The audit pages are sortable tables, and every list chooses its page size.** Traces, Ripple reports, Continuity findings, Entities, and Assertions each render as a table whose column headers sort: a click orders by that column, a second click reverses it, and the sorted column carries an arrow and `aria-sort`. Ordering reads values carried on the row rather than the text in the cell, so cost and tokens and confidence sort as numbers, times as times, and severity and status by weight (high before medium before low, open before dismissed before resolved) instead of alphabetically. Column widths are fixed, so a long value arriving under a sort (a provider error in the Traces purpose column) wraps inside its own column rather than pushing the columns beside it out of the window. The pager gains a 25/50/100 choice kept per page in the browser, and the Traces window widens from 200 rows to 1000 so a sort by cost covers more than the last hour. Entities and Assertions keep their checkboxes, batch bar, and row actions; Assertions states active or inactive in a column of its own instead of a prefix on the text.

- **Settings lists what has been billed, action by action.** The Spend tab gains a searchable table of every billable action with its tokens and cash cost, grouped the way the calls were made: a graph build is one row covering its per-scene calls, a ripple preview one row covering its judge, continuity, and synthesis calls, and each question its own row with the question shown under it. Grouping goes by script and by how far apart the calls came rather than by run or change-set id, so a build whose run row has since gone still reads as one action instead of fragmenting into hundreds. Columns sort, the table pages, and search filters the rows in the page with the header count reading "N of M action(s)".

- **A graph build can be cancelled.** The progress panel gains a Cancel button that asks for a second press before it acts. The run stops after the scene in flight, closes as cancelled, and its pending cache rows go, so pressing Build graph later resumes from the completed scenes and bills only the scenes still to do. Scenes already extracted keep their facts, and the script drops back to partially ready (or to unanalysed when the cancel comes before any scene finished). A build over a run abandoned some other way, a closed tab or a restart, now replaces the leftover rows instead of colliding with the extraction cache's unique key.

- **The reader toolbar reflects whether a graph exists.** Three controls used to look the same with or without a graph. The Graph button is a live link only when there is a graph to open, and a disabled control carrying a tooltip otherwise. Build graph, when nothing has been built, is the one action the rest of the screen depends on, so it is amber with a slow halo pulse that marks it as the first step, a steady ring under reduced motion; the halo is the second, non-colour channel for a reader who cannot see the amber, and both fall away once a graph exists, when the button reads "Update graph" if scenes changed or goes disabled if the graph is current. The model-name chip is gone from the reader and the library: the model is chosen in Settings and only Gemini is in use, so the name was noise; the "no model" prompt stays, since it points at a step. The empty script-graph page now links to that script's reader, where Build graph is, rather than to the library.

- **See ripple waits for a graph to exist.** Editing a line on a script with no graph lit up See ripple, which then previewed an edit against nothing; the only actionable step on an unbuilt script is Build graph, which is already in the toolbar. The button now stays off until the script has an assertion to compare against. The test is the graph's existence, not its build status, so a seeded or partly-built graph enables it too, and the in-place build reloads into the ready state when it finishes.

- **A fuller character name widens the character instead of forking it.** A cue that strictly extends a character the graph already knows, or is extended by it ("LUBOV" then "LUBOV ANDREYEVNA"), now resolves to that one character with the other surface kept as an alias, so a play that cues a speaker by first name in one scene and by full name in another builds one node rather than two. The match is deterministic and conservative: it fires only for cast, only on a whole-word name extension, and only when a single character stands in that relation, so two characters sharing a first name ("MARY ANNE" and "MARY JANE") stay distinct and a bare "MARY" that could be either forks rather than guessing; a prop or location never prefix-merges. The duplicate-review panel stays the safety net for what this deterministic rule leaves behind.

- **Ripple imports stage plays, not only screenplays.** Public-domain plays (Shakespeare, Wilde, Ibsen and the like) name their structure in acts and scenes rather than INT./EXT. sluglines, so they used to import as one unstructured block and lost every scene boundary. A new stage-play format and adapter reads that shape: an act heading in numerals or words ("ACT I", "ACT 1", "FIRST ACT") and a scene heading ("SCENE", "SCENE II", "SCENE I. A platform before the Castle") set the scene boundaries, an act that holds no numbered scenes is itself one scene, the setting that opens a scene becomes its heading so a location reads out of it, an all-caps name ending in a period is the speaker, and bracketed lines and Enter/Exit/Exeunt lines are stage directions rather than dialogue. The Project Gutenberg licence wrapper and the front matter before the first heading are dropped, and the title is read from the "Title:" line. Detection keys on act and scene headings above a run of all-caps cues with no sluglines present, so a screenplay still routes to its own parser. Verified on the three dominant Gutenberg formats.

- **The Ask answer states its true grounding and stops calling a sample its citations.** The grounding line read "Grounded in N assertions across 6 units", where the 6 was the display cap on the evidence panel, not the number of units the evidence spanned: a packet of hundreds of assertions covers far more than six units, so the sentence understated the grounding, and the panel titled "Cited units" showed the first six packet units while implying the model had picked them. The answer now carries the true distinct-unit total beside the assertion count, the sentence reads "across {total} units", and the panel is retitled "Evidence" and labels itself "sample of 6 of {total}" whenever it is capped. The model's own citations were never computed, so nothing claims they were; the exported Markdown says the same.

- **Scanned PDFs import correctly through OCR.** A scanned screenplay run through the Tesseract path parsed to zero scenes, from three compounding faults. OCR discards the geometry a text layer carries, so the line builder threw away the blank lines that separate blocks and numbered every line one below the last, collapsing each page into a single block that hid every heading; blank lines now advance the vertical cursor past a full block break, so blocks separate. A scene heading, and on the OCR path a character cue, is forced onto a block of its own, because a screenplay leaves no blank line between a slug and its action or a cue and its dialogue. And because OCR flattens the indentation that tells a cue from action, the OCR path classifies by shape instead: a short all-caps name line is the speaker, and the line after it is their dialogue. A 7-page scan now imports as 28 scenes with clean headings, 35 speakers, and 42 dialogue lines, marked for review as every OCR import is. The text-layer path is untouched.

- **Extraction drops pronouns, screen text, and stray directions instead of writing them as entities.** The validator gained a name-quality rule: a pronoun the model resolved to a fresh entity instead of its antecedent ("He", "She"), a group label standing in for one ("Two Characters", "second person"), or a line of screen text lifted into a name ("PERMISSIONS UPDATED. CONTACT YOUR SUPERVISOR") is dropped before it reaches the graph, with the reason recorded. Unnamed roles a screenplay leaves generic ("Nurse", "Woman", "Surgeon") are kept, because those are valid characters. The deterministic pre-pass now applies the same filter, plus a transition-and-shot guard, on both the cast and location it derives from cues and headings: a flattened scan can type a transition, a shot, or a montage heading as a character cue or a slugline ("END INTERCUT", "ANGLE ON - THE FOOTLIGHTS", "MONTAGE - EIGHT PERFORMANCES"), and none of those becomes an entity. A cardinal count leading a noun is an anonymous group of characters, not one named character ("Two men", "Three cops", "Several workers"), so it is dropped from cast; the rule is scoped to cast alone, since a prop, set dressing, or location legitimately carries a count or plural noun ("Six monitors", "14 Stannary Lane", "one wall of books"), and a bare number ("Seven") or an ordinal role ("Second Officer") is kept. Across the corpus the guards dropped junk from every door and touched no valid name, so a roster question ("list the characters") reads clean rather than surfacing extraction noise.

- **Ask the graph answers rosters, scene lists, and accent-typed names.** A pass over the kinds of question a first-time reader asks turned up three failures, all now fixed. Enumeration: "who are the characters", "list the props", "what locations appear" answered "the graph does not record the full list" because the packet carried entity counts but no names, so the model could only name entities that happened to be in the sampled assertions; the packet now carries an entities-by-type roster (count and names per department, names capped per department with the true count kept beside them), so the full cast, props, and locations list. Scene enumeration: "list the scene headings" and "what is the opening scene" were rebuilt from sampled assertions and came out partial; the packet now carries the full ordered scene list, so they answer completely. Accents: keyword retrieval folded case but not diacritics, so "what does Bela use" missed "Béla" and answered "the graph does not record it" while the accented spelling answered fully; question terms and the assertion text are now both diacritic-folded, so an accent-less name finds its entity. Reach: a question that names nothing the keyword pass can match, a scene-anchored or aggregate one ("what happens in the last scene"), fell back to a 40-row sample of the graph and so missed the scenes it did not sample; that fallback now carries the whole graph up to a cap set above the largest demo-corpus script, since a user query is infrequent and costs a fraction of a cent. A keyword-scoped question still sends its focused hits, so its grounding count stays honest. Verified live on a 32-scene, 88-entity screenplay.

- **The Ask path calls Google's `google-genai` SDK directly.** Ask the graph now answers through the official `google-genai` library instead of KeyCall's HTTP path, so a Google SDK generation is imported and called at runtime on every asked question. Extraction and judgement stay on KeyCall for its native schema enforcement and typed errors; the query path needs neither. The adapter satisfies the same provider contract, mapping the SDK's response, token usage, and finish reason onto Ripple's `GenerationResult`, so the audit ledger, budget gate, and fallback-on-availability behaviour are unchanged. Same credential, same model ids; only the transport differs.

- **The ripple preview shows how it was computed, verdict by verdict.** A new card on the preview renders the judgement the graph diff came from: a tally (assertions judged, then changed, removed, held, and new), one row per changed, removed, or new edge tagged with its verdict, and a "verification dropped" section listing what code checking threw out and why (a verdict on an unlisted assertion, a `holds` whose cited evidence text was gone). An **Open full trace** button opens that run's complete trace in the TraceAct viewer; the run's trace id now rides on a successful preview, not only on a failed one. A preview spanning more than one scene combines the per-scene judgements into one card rather than showing nothing.

- **Ask the graph fences untrusted text and caps the question length.** The two regions a hostile script or query controls, the user's question and each quoted screenplay line, now reach the model wrapped between markers that share a per-request random tag, carried in the packet as `sentinel` (`query.v6`, a spotlighting technique). The tag differs on every request and the screenplay cannot predict it, so a planted line cannot forge the closing marker to break out of its fence or claim the trusted region has resumed; the system prompt states the convention and instructs the model to read fenced text as data and obey only the system message. Because only the tag value changes per request, the prompt version is stable across calls. Alongside it, the ask route caps a question at 1024 characters and refuses a longer one, which denies a large injected instruction a path in through the query box and bounds a single ask's input tokens before any provider contact. Datamarking was considered and left out for now; deterministic English-only answers were rejected as unworkable for non-English questions.

- **Ask the graph always makes a live call, and handles mixed questions.** Retrieval no longer gates the model: the packet is script facts (title, scene, entity, and assertion counts, plus entities broken down by department type, from the database) plus assertions, keyword-scoped when the question names graph content and a whole-graph sample otherwise, so "how many scenes are in this script" and "how many cast members are in this play" both get a written answer instead of the canned "nothing answers that". The rewritten query prompt (`query.v6`) treats the question as untrusted text: parts the packet answers are answered with scene citations, and parts about anything else, the software, the model, or instructions embedded in the question, are passed over in silence rather than followed. They draw no answer and no announced refusal, since a decline per probe is noise and tells a prober which probes registered; only a question about the screenplay's own content that the graph cannot answer gets one short sentence. The scope rule gates on provenance rather than names, so a screenplay that depicts a ripple crossing a pond, or one about a company building software called Ripple, stays answerable from its own graph while the system running the query stays unanswerable, being absent from the packet. Screenplay text reaches the model as cited evidence, so a line planted in a script to address the assistant is reported as what the line says, never acted on. Scene identity in the packet no longer depends on scene numbering: an unnumbered script reached the model with every scene null, so a fact the graph recorded ("which scenes use the mug") read as unrecorded; the packet now carries the scene heading beside the number, and the answer names scenes by heading when there is no number, without ever inventing one. Verified live with a compound question mixing a valid count with two probes: the count answered correctly (32, matching the database) and both probes were declined. The no-model fallback now states the script facts too, and the query output cap rises 600 → 2048 so hidden reasoning cannot truncate the answer. Prompt versions now have a review surface: an internal registry records each live version, where its text lives, and what changed between versions, with a test failing any version bump that skips the registry; the exact text of every past call remains on its trace and in the `model_calls` audit row.

- **Scripts and history get a pane each, both searchable and resizable.** They shared one sidebar, which stops working at scale: a hundred scripts above a hundred questions is one long scroll. Scripts now hold the left pane and question history a new right pane, each with its own scrollbar, its own instant-search box (filtering the rendered rows, no request), and its own "nothing matches" line. Both panes collapse from the toolbar and remember it, and both carry a draggable edge: pointer or arrow keys, bounded, with the width persisted per pane. History rows carry their timestamp, and a newly asked question appears at the top of the pane without a reload.

- **The ask page is laid out as one centred column.** The question, its answer, and the citations share a single 860px axis with generous padding instead of stretching the window: the ask box is one pill (search glyph, field, and Ask button reading as a single control, focus ring on the whole thing), the grounding line and its badge sit on one row with the badge right-aligned, and **Export answer** moves to the toolbar, appearing only once there is an answer to export. The grounding check also stopped crying wolf: a name that wraps a grounded one ("the blue sedan" against a grounded "Blue sedan") is the same mention, so containment now counts in both directions.

- **Ask the graph gets a proper empty state, and builds in place.** A script with no graph no longer renders a greyed-out ask box under a warning bar: the page shows what is missing and one centred action — **Build graph**, or **Choose a model** when none is configured. Pressing Build runs the extraction loop on the ask page itself, swapping the empty state for a progress view: which scene is extracting, scenes done of total, a progress bar, the spend so far (tokens and cost), and the pace per scene. The loop is the same one-scene-per-request pattern the reader uses, each scene committed on its own, so leaving the page pauses the build and pressing Build again resumes from the unfinished scenes at no repeated cost. When the run finishes the page reloads into the live ask box.

- **Ask the graph gets its own left pane, exports answers, and checks its own grounding.** The page drops the shared navigation for a pane of its own: every script with its accepted-assertion count (click to switch what you are asking), and below it the chosen script's question history. Every question was already logged for audit; clicking a past one replays its stored answer at zero cost (the note says when it was asked, and cited units are resolved from whichever of the stored assertions still exist), and fills the question box so Ask re-runs it fresh. **Export answer** downloads the rendered answer as Markdown: question, answer, grounding stats, entities, and cited units. And a written answer is checked against its evidence: if it names a graph entity that was not among the assertions handed to the model, the answer carries a "names outside grounding" tag listing them; otherwise it carries "no ungrounded entities". The check covers entity names on whole words, case-insensitive, and is skipped for stored replays, since the graph may have changed since the answer was written.

- **Shiplock guards the docs against the code.** The repo now carries a `shiplock.toml` and runs [Shiplock](https://pypi.org/project/shiplock)'s deterministic release checks inside the test suite (`tests/test_docs.py`): declared public docs present, banned words, version alignment between `pyproject.toml` and `ripple.__version__`, the architecture doc's module list against `ripple/`, the per-file manifest against the shipped sources, and README link hygiene. `shiplock check` at the repo root runs the identical gate from the terminal. Its first sweep caught one stray banned word in ARCHITECTURE.md, fixed in the same change.

- **Lists act on many rows at once, and the Traces page opens the full viewer.** The shared list surface (Entities, Assertions) gains a checkbox per row, a "Select all matching" control that honours the current search, and a floating action bar that runs one request over the whole selection. On Entities: Merge selected folds every ticked duplicate pair (a pair whose entity was already absorbed by an earlier merge in the same batch is skipped, not fatal), Keep selected separate records them all as distinct, and Delete selected removes entities behind a typed confirm that names the assertion count the cascade will also remove. On Assertions: Deactivate selected takes the ticked rows out of the active graph while keeping the rows, and Reactivate selected returns deactivated rows to it (the page now shows deactivated assertions too, muted and marked, and a reactivation that would collide with an active row holding the same dedupe key is skipped, not fatal). Each action lights only for the selected rows that support it. The Traces page keeps no checkboxes on purpose (deleting a model-call row would move the spend totals) and instead gains an **Open in TraceAct viewer** button that launches (or reuses) the local viewer reading Ripple's whole `data/traces` log in map view, the page-level companion to the per-row trace open.

- **Duplicate entities are caught, and the ones that got through can be merged.** Extraction now resolves a proposed name against existing aliases too: a name one entity already holds as an alias extends that entity instead of forking a new one, unless two entities share the alias, in which case a fresh entity is created rather than guessed. For forks already in the graph, the Entities page leads with suspected duplicates: same-type pairs where one name appears whole inside the other ("Monitors" inside "Dispatch monitors") or one's name is recorded as the other's alias, with pronoun surfaces ignored and the safest pairs listed first. Merge moves every assertion, attribute, alias, and speaker link onto the more-cited entity, records the decision as an accepted `merge_entities` change set on the Reports page with a snapshot of what the absorbed entity was, keeps its name as an alias so later mentions resolve, and bumps the script version so a preview drafted against the pre-merge graph refuses as stale. Keep separate records the pair as distinct and the suggestion stops. Merging two entities that both hold an active value for the same attribute key keeps the survivor's value and deactivates the other, which also holds for rename absorption.

- **An accepted ripple no longer re-bills its scene.** Accepting a judged edit already applies the verdicts and new items to the graph, so the whole-scene re-extraction that Update graph offered afterwards duplicated paid work. Acceptance now stamps each edited scene's new content as extracted, under the same synthetic-run shape the draft link uses to carry a cache, and only when the pre-edit content had a completed extraction under the current prompt and selected model: the stamp extends an extracted graph, never invents one. The judgement also widens to cross-line effects: every entity the edited lines name brings its scene-local assertions to the judge, which holds them unless the proposed text explicitly contradicts what they state ("she sets the knife down" against a carries edge cited two lines up), and a removal of such an untouched fact is admitted only when the edit names the entity.

- **Graph builds cost a fraction of what they did.** Four changes, all measured against the audit ledger that showed hidden reasoning and answer verbosity carrying ~90% of a build's spend. Every model call now caps thinking at a medium level (hidden reasoning bills at the output rate and was 38% of a build). Extraction speaks a terser output format (`extract.v5`): short field names, short unit ids in place of 36-character UUIDs on every cited item, and endpoint kinds inferred from the ids; the judgement pass (`judge.v5`) speaks the same format for new items. A deterministic pre-pass records what code can read before the model is called: the speaking cast from dialogue cues and the location from the heading, written as `system`-provenance rows citing the cue and heading lines, with the prompt handing the model their fixed ids. And extraction escalates instead of failing: a malformed, truncated, or empty reply from the main model is retried on the configured fallback model in the same pass, each attempt audited, which makes a cheap main model with a stronger fallback the recommended pairing. The validator also drops any evidence span that reaches past its line's end, keeping the item and losing the misquote.

- **A linked draft's reader tints what changed against the predecessor.** The same revision tint that marks accepted ripples now also marks the words a new draft changed: each edited line in a changed scene word-diffs against the predecessor line it revises (paired deterministically through the lineage the link already wrote, with a similarity pass for the edited lines the link leaves unlinked), heading edits tint in the scene header, and a wholly new line tints whole. A scene the previous draft did not have is chipped "NEW IN THIS DRAFT" instead of being tinted word by word, and the previous draft's own reader stays unmarked. The predecessor wording is the earlier baseline, so it wins over the in-draft accepted-edit baseline when both apply.

- **Build graph is gated on billable work.** With the graph built and every scene's content matching its cached extraction, the button disables and its tooltip says why. When scenes changed since the last build (an accepted ripple, an added or restored scene, a linked draft, a switched model), it reads Update graph and counts the changed scenes in its tooltip; only those are billed, because unchanged scenes replay from the extraction cache. The gate reads the same content hashes the cache keys on, so every path that changes a scene re-enables the button with no bookkeeping of its own.
- **Chargeable actions report their cost in money.** Graph builds and updates show tokens and dollars live in the progress counter and the finished label; the ripple preview's footer reports what the run spent (answer, hidden reasoning, and input tokens, plus the cost); the Traces page prices every audit row and totals the whole ledger in its subtitle. Prices come from the bundled `rates` registry (pypi.org/project/rates), looked up by provider and model with hidden reasoning billed at the output rate; a model the registry does not price shows its tokens alone rather than an invented figure, and a cached run reports zero. The registry ships bundled with the package and cannot fail to load; the one absence Ripple handles is `rates` itself not being installed, in which case tokens show alone.
- **Traces carry full payloads.** Tracing flips from redact-by-default to record-by-default: every model call's complete prompt, reply, and token usage (answer, hidden reasoning, input) is recorded on its trace, along with each preview's edits, each query's question and answer, each import's filename and title, and each confirmed rename's payload. KeyCall's own spans keep their internal redaction, so Ripple records its own model events beside them. The truncated audit row now also stores the reasoning-token count (`model_calls.reasoning_tokens`, shown on the Traces page), so a cut-off reply's budget is accounted for in the records instead of guessed at. Traces stay in `data/traces/`, local and out of version control; credential-shaped values are still caught by value-pattern redaction.
- **Truncation blames the reasoning budget, not the model's limit.** Models that reason before answering bill the hidden reasoning to the same output budget as the answer, so a reply can stop at the cap with the visible text well short of it. Reasoning tokens now flow through from the provider and the truncation message states them as the cause ("1476 answer tokens plus 6716 hidden reasoning tokens against the 8192 requested"); without a reported count, the budget is named as the likely cause instead of mis-reading the shortfall as the model's own smaller limit. The judgement output cap also rises from 4,096 to 8,192 tokens, matching extraction, so a reasoning model has room to think and still finish; only produced tokens are billed, so the headroom is free on models that answer within it.
- **A failed preview says what stopped and offers the trace.** The truncation error now names the model, the output tokens it produced against the tokens Ripple requested, and the finish reason, and says when the model's own output limit is the smaller one; the continuity pass's advisory note carries the same detail. - **The Entities and library pages read the graph in a handful of queries.** Entities used to run two queries per entity plus the duplicate detector's two per candidate pair, 2,187 statements and 2.6 seconds over the demo corpus; aliases and citation counts now arrive in one grouped read each and the detector counts citations once per script, 53 statements and under half a second for the same page. The library reads its import records, scene counts, and page counts across all scripts at once instead of four times per script.

- **One clock, one identifier parser, one scene label.** The services share `now()`, `as_uuid()`, and `Scene.label` (the printed scene number, or a dash for an unnumbered scene) instead of each carrying its own copy, and every model call records its outcome through the same two ledger helpers.

### Removed

- `GET /api/scripts/{id}/runs`, an extraction-run listing nothing called, and a stylesheet the pages never loaded.

### Fixed

- **A plan stated on the last allowed tool call is a plan, not a stop.** When the per-turn ceiling fell on the call that stated the plan, the card rendered with Go ahead beneath a reply saying the turn had stopped without finishing. The stated plan closes the plan stage whichever call states it.

- **A written explanation is no longer cut off mid-sentence.** The model's hidden reasoning counts against the same output ceiling as its prose, and the 400-token cap on the explanation left 19 tokens for the answer on a three-line edit. The ceiling is 2,048.

- **Archer's Ibsen editions import as plays.** Hedda Gabler from Project Gutenberg was refused as having no scenes: its acts read "ACT FIRST." and the stage-play parser knew "ACT ONE" and "FIRST ACT" but not the ordinal after the word. The same edition sets a blank line between each cue and its speech, which the parser read as the end of the speech, so the play came in as stage direction with a dialogue warning; a cue now waits across the blank for its speech. A wrapped sentence that left the word "scene." alone on a line no longer opens a scene, and a cue with a title abbreviation ("MRS. ELVSTED.") is one name rather than a speaker called MRS with the speech "ELVSTED.", a bracketed stage direction that wraps over several lines stays a direction until its bracket closes, and "THE END" is a direction rather than a speaker.

- **Continuity findings survive their own validation again.** The evidence packet exposed each item's unit id while the system prompt told the model to cite assertion ids, so every citation failed the validator and the continuity pass silently returned zero findings. The packet now carries the assertion id, and the demo corpus's planted conflicts (a repainted sedan against a later scene that still calls it blue, a cut forklift a character hides behind later) come back as warnings with citations.
- **The judge reports what an edit adds, a stunt included.** Its instruction covered replacement but not addition, and the new-material arrays were optional, so a line adding a dangerous action ("The sedan peels out hard, fishtailing across the wet dock") produced no new requirement. The judgement schema now requires the new-entity and new-assertion arrays (an empty array is a stated answer, not an omission), and the prompt extracts added material the same way, naming a fall, a crash, or hard driving as a stunt the scene requires.
- **Swapping an object for one of another type reads as a removal and an addition.** The diff paired edges by subject and predicate alone, so "Sc 14 requires forklift" becoming "Sc 14 requires sedan fishtailing" showed as one changed row, hiding both the lost requirement and the new one. The pairing now includes the object's entity type, so a like-for-like change still reads as a change and a cross-type swap splits in two.
- **An added edge names its scene.** A brand-new edge whose subject was a scene rendered the scene's raw id in the preview overlay; it now reads "Sc 14".
- **Rejecting or undoing a proposal resolves its findings.** Continuity warnings argue against a specific proposed edit, but they used to remain open after that edit was rejected or reverted, inflating the findings count with rows about text that no longer exists. Both paths now resolve the proposal's open findings, stamped with when.
- **A one-word edit can no longer read as "nothing changes".** Editing "Six monitors" to "Twelve monitors" produced "No graph change" because the graph never held the monitors; with the complete ground truths the same edit now answers with the count attribute change at medium severity. The preview's summary also states what it judged ("All N stored facts the edited lines support still hold") and, when an edited line supports nothing stored, says the graph is incomplete rather than implying the edit has no impact.
- **Ground-truth seeding could touch a user's upload.** Startup seeding selected scripts by title, so uploading a script named NIGHT FREIGHT and restarting would mix the bundled ground truth into its extracted graph, with evidence spans pointing at another document's lines. Scripts now carry an `origin` column: the startup importer marks its own imports `bundled`, and seeding refuses everything else. Existing databases get the column on start, with pre-existing demo scripts re-marked only on evidence (a system-provenance graph and no extraction history), never on a title match alone.
- **The confidence numbers explain themselves.** The decimals on requirement rows, attribute-change cards, and graph detail panes now carry hover text ("Confidence: the model's certainty this fact is stated, from 0 to 1"), reachable by keyboard and named for screen readers.
- **OCR of a multi-page scan wrote page images into the working directory.** pdftoppm treats any trailing argument, including `-`, as a filename prefix, so a two-page scan dropped `--1.png` and `--2.png` beside the app and fed OCR broken input. The rasteriser now runs one page per pass with the output root omitted, the only mode that writes to stdout, so nothing touches disk and every page reaches Tesseract; a regression test asserts an OCR import leaves the working directory empty.
- **A removal must be visible in the edit (`judge.v3`).** The judge could answer `removed` for edges whose entities the proposed text still names, and for facts the edited line never stated, because uncited facts fall back to citing a scene's first unit; a count change then produced five phantom removals and a false orphan warning. Two validator guards now downgrade those to holds: a removed verdict stands only when some endpoint was named in the current text and is gone from the proposed text, and an attribute can only change through a line that visibly carries its value. Both downgrades are recorded in the audit row.

- **The launcher finds a working Python instead of trusting PATH's `python3`.** A version manager's pin can hold `python3` below 3.11 while newer interpreters are present and working; the launcher now reuses a valid venv without needing a system Python at all, and otherwise probes version-named binaries and the usual install locations, judging each candidate by running it.
- **Predicates print as words in the UI.** Edge labels, requirement rows, detail panes, and the Assertions page show "appears in" rather than `appears_in`; the stored vocabulary is unchanged.
- **The launcher stops a stale server instead of adopting it.** `launch.command` now terminates any running Ripple instance before touching the environment, so two servers can never share the SQLite file. It also verifies Python 3.11 or newer with an actionable message, rebuilds a broken virtual environment instead of failing on it, and takes over a port held by another Ripple instance rather than skipping past it.
- **The virtual environments and runtime data are excluded from Dropbox sync.** The launcher marks `.venv` and `data/` with the ignore marker on every start, so sync can no longer invalidate the environment mid-run or replicate `data/secrets.env` off the machine.
- **Server rejections reach the page as sentences.** A 422's field-error array rendered as "[object Object]" and other failures as "Request failed (500)"; `api()` now assembles a readable sentence from whatever the server sent, error-code badges print their words instead of snake_case, and the error page labels its number as an HTTP status.
- **Import warnings survive the library's reload.** The import outcome and its warnings are stashed across the reload that shows the new row, instead of being wiped after 0.9 seconds.
- **Forgetting a key asks first.** The Settings Forget button confirms before deleting the stored credential.
- **`tools/seed_graph.py` explains an empty database.** Run before the corpus was ever imported, it printed success and seeded nothing; it now exits with an error naming the fix: launch the app once so the library imports the corpus.

- **A selection made before the graph's own layout settled could render without dimming the rest of the graph.** `draw()` defers itself with `requestAnimationFrame` when the canvas reports a momentary zero size (right after navigation, a pane toggle); the dim pass was a separate statement after that call, so a selection made during that window ran the dim check against zero nodes and the drawn ones showed up afterward with no dim state at all. The dim pass is now `draw()`'s own completion callback, so it runs against the nodes on the page, whether that's the immediate draw or the deferred one.
- **Accepting a "changed" assertion applied nothing.** The update handler deactivated the old edge and then routed through the addition's reactivation fast path, which re-activated the row it had just deactivated and never read the new edge. Every accepted update now writes the new edge from its payload, and undoing one restores the old edge.
- **Failed and refused model calls now reach the ledger.** A judge call that failed, and a budget refusal, wrote their audit rows and then lost them when the request's transaction rolled back, so billed work was invisible to the spend cap. A failing preview now commits its audit rows and the model-availability marks before the error propagates; nothing else is pending at any point the preview can fail.
- **A judged scene is never re-billed.** A preview retried after a failure elsewhere replays each already-judged scene from its recorded reply, written to the audit as a `cached` call with zero tokens. Judge calls are also linked to the proposal they produced through the calls the preview itself made, instead of a newest-unlinked query that could attach another request's calls.
- **An empty judge reply no longer passes as "No graph change".** A schema-valid reply that skipped listed items used to default every one of them to `holds`; any coverage miss now fails the preview with `incomplete_judgement` and an `incomplete` audit row.
- **A hold cannot survive on deleted text.** The vanished-evidence guard accepted any in-bounds offset pair without comparing content; the offsets escape is gone, and only the evidence text still appearing in the proposed line keeps a `holds` verdict alive.
- **Stale proposals are recorded as stale.** The status write raised with the 409 and rolled back with it, leaving the proposal pending and matching the preview cache forever. The web layer now re-applies the status in a fresh session, and the same path records a proposal whose unit vanished as `failed`.
- **Entities created through accepted changes keep their cased names.** Operation payloads carried the normalized key, so a judged new prop "The Brass Key" was stored and displayed as "brass key". Payloads now carry the display name; lookups normalize either way.
- **Screenplay-derived text is escaped before it reaches the page.** Names, unit text, evidence, warnings, and model output flowed into `innerHTML` unescaped in the reader, both graph views, Ask, Settings, and the library, so an uploaded script could run markup in every page that rendered it. A shared escape helper now covers all of them.
- **Extraction run status tells the truth.** A run that finished with failed scenes reported `ready`; it now reports `partially_ready`, and `ready` is reserved for a run every scene of which completed. A run whose every scene is served from the cache finishes immediately instead of staying pending with nothing to claim.
- **Settings validation never touches the process environment.** A key under validation was written into `os.environ` for the duration of the network call, so a concurrent extraction could read the wrong key; the candidate now rides the call itself and is discarded.
- **The preview's continuity context is scoped and ordered.** Open findings from other scripts no longer enter the evidence packet, and the earlier/later split anchors on the earliest edited scene in script order rather than whichever edit came first in the request.
- **Invented scene numbers are gone everywhere.** The "Sc —" fix reached only one of three label maps; preview citations and continuity payloads could still name a position as a number that belonged to a different scene. One shared label map now serves the web layer, the preview, and continuity.
- **New-assertion endpoints resolve by type.** A judged edge citing an existing entity by name matched on the name alone, so a prop and a transportation entity sharing a name could take each other's edges; matching is now constrained to the types the predicate accepts on that side.
- **Evidence offsets are a pair or nothing.** A half pair like `(null, 42)` survived validation and silently slid to the start of the unit; both offsets now arrive together and ordered, or neither does. The judge also refuses an out-of-range confidence instead of clamping it, so a claimed confidence of 87 no longer becomes a trusted 1.0.
- **The extraction cache key covers the prompt.** Editing the rules or the schema changed every prompt without changing `PROMPT_VERSION`, so cached extractions were served against a prompt they never saw; the content hash now folds in a fingerprint of the prompt material.
- **Opening a script is a POST, not a side effect of the GET.** The reader's GET wrote `last_opened_at`, so a prefetch or a crawler reordered Recently opened; the reader and script-graph pages now report the open themselves.
- **Stale links answer honestly.** `/ask` with an unknown script fell back to the newest script and `/findings` widened to every script, both silently; both now answer 404. The graph-lock notice is scoped to the page's own script, and one script's deletion preview no longer counts every script's findings.
- **Unexpected server errors answer in the app's own voice.** A `ValueError` from the extraction service surfaced as a bare 500, and any non-HTTP exception on a page route bypassed the error view entirely; both now render the in-app error page (or JSON on API routes) with the details kept to the server log.
- **The graph page stopped burning a core.** A selection made with the requirement pane collapsed requeued `draw()` through `requestAnimationFrame` forever against a zero-size canvas; the retries are bounded. The expanded view's selection also applies its highlight to the clicked node (it compared labels, so same-named nodes cleared each other), survives a window resize with its dim state, and the reader's mini graph no longer traps page scrolling under the wheel.
- **The preview overlay's buttons follow the server's state.** Rejecting a proposal cleared it from the page so a later Accept could not hit a rejected proposal, drafts compare through non-breaking spaces so a retyped line stops counting as edited, See ripple disables when no draft exists, and switching lines mid-load can no longer let the first line's late replies overwrite the second's panes. Ask sends one question at a time.
- **Seeding survives edge input.** A heading-only scene and a ground-truth row with an empty name both crashed the startup seeder; both are skipped now.
- **Undo covers entity operations.** A change set holding `create_entity` or `update_entity` had no inverse mapping and crashed the undo with a bare KeyError; both invert now, and acceptance and undo traces record the change set and unit they were given even when they fail.
- **The suite runs without the live credential.** The web fixtures point the secret store at an empty file through `RIPPLE_SECRETS_PATH`, so startup cannot repopulate the key a test just removed, and the settings and provider tests run against stubs instead of the live endpoint.
- **Text selection was unreadable.** The browser default left grey secondary text on a pale blue block.
- **Ask the graph sent a null script id**, because the page read the script from a query parameter the server had not put there. It now comes from the server, which also handles the fallback to the most recent script.
- **Unnumbered scenes were given invented numbers.** Intercut sub-scenes carry no number of their own, and substituting the position produced a sidebar listing two scene 9s.
- **Accented character cues were parsed as action.** The cue pattern used `[A-Z0-9]`, so `MATÍAS` and `BÉLA` fell through to action lines and their dialogue lost its speaker. The pattern is now Unicode-aware. Found by rendering the third demo script, which was written to carry this trap.

## [0.1.0] - 2026-08-01

### Added

- **Import adapters for four formats.** Fountain, Final Draft XML, PDF, and plain text behind one contract: detect, extract, parse, validate, return a shared typed result. `import_screenplay` never raises for bad input; a file that cannot become a screenplay returns a rejected result with a stable code.
- **Content-based format detection.** File extensions are hints that can break a tie between two text formats and never override a content signal.
- **Structural screenplay check.** A parsed document is judged on scene count, character-and-dialogue presence, dialogue share, and mean action length before it is accepted, so prose and invoices are rejected with stated reasons.
- **PDF layout parsing via pdf-inspector.** Local classification and position-aware extraction, no network calls and no models. Blocks are classified against the page's own modal left margin and split on vertical spacing, page break, or horizontal offset. Scanned PDFs rasterise through `pdftoppm` and read through `tesseract`, both local; when either is absent the import is rejected with `ocr_unavailable`.
- **Hardened XML parsing.** Final Draft files go through `defusedxml`. External entities and entity expansion are refused, pinned by billion-laughs and XXE tests.
- **TraceAct 0.12.0 instrumentation** on the `script.import` workflow, with automatic input capture disabled and the `ai_prompts`, `api_keys`, `http`, `filesystem_paths`, and `env_vars` redaction presets. Tests assert that no screenplay line, character name, or filename appears in any trace.
- **Demo corpus.** Three original screenplays, each authored in Fountain and rendered to Final Draft XML, PDF, and plain text by `tools/render_screenplay.py`. Each ships a `dependencies.md` recording expected entities, assertions, and planted dependency chains.
- **`launch.command`.** Path-safe bootstrap that creates the virtual environment, installs the package, and runs the test suite.
